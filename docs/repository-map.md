# What is in this repository, and why

This repository holds one method and the evidence for it. The method is BARCS,
a beta-binomial regression for pooled CRISPR screens. Almost everything else
here exists to answer one of four questions about it, and the fastest way to
navigate the repository is to know which question a file belongs to.

If you are returning to this project after time away, read this file first,
then [`docs/barcs-external-method-comparison.md`](barcs-external-method-comparison.md)
for the narrative of what the benchmarks found.

## The four questions

| # | Question | Why it has to be asked | Where it is answered |
|---|---|---|---|
| 1 | Does the regression reduce to original CB² where the two overlap? | BARCS is sold as an *additive* path inside CB2. If it silently changed two-group answers, existing users would be broken. | `examples/cb2_generalization_*.R` |
| 2 | Is it correct on data where the truth is known? | Real screens have no ground truth, so calibration and power can only be measured on simulations. | `examples/crispulator_*.R`, `examples/simcrispr_*.R` |
| 3 | Does it hold up on real screens against published results? | Simulations can flatter a method that matches their generative assumptions. | `examples/{sanson,chronos,gse70038,waterbear,liang}_*.R` |
| 4 | How does it compare with the methods people actually use? | "Better than nothing" is not a claim worth making. | the `*_head_to_head*` and `*_moi_10k_*` scripts |

## Reading order

Nobody should read twenty benchmark scripts. In order of how much they explain
per minute spent:

1. **[`README.md`](../README.md)** — what BARCS is and how it differs from CB².
2. **[`docs/barcs-input-output-examples.md`](barcs-input-output-examples.md)** —
   input table, function call, output table. The shortest path to knowing what
   the method actually does.
3. **[`docs/barcs-external-method-comparison.md`](barcs-external-method-comparison.md)** —
   the findings, including the ones that went against BARCS.
4. **[`sections/barcs-results.tex`](../sections/barcs-results.tex)** — the same
   findings in manuscript form, or read the built PDF under `output/pdf/`.
5. One benchmark script, if you need to check a specific number.

## The method itself

| File | What it is |
|---|---|
| `CB2/` | The R package, as a git submodule. This is the shipped artifact. |
| `R/bbreg.R` | A dependency-free copy of the regression layer used by the benchmark scripts, so a benchmark can be read and run without installing the package. Keep it in step with the package. |
| `R/method_palette.R` | One colour per method, shared by every figure so a method is the same colour throughout the manuscript. |
| `tests/run_tests.R` | Tests for the analysis-side copy. The package has its own suite under `CB2/tests`. |
| `python/barcs/` | A Python port of the guide-level regression, with no R dependency. Covers the inference path only -- not the later guide-to-gene statistics, and not dispersion moderation. Checked against R to eight significant figures by `python/tests/`. See [`python/README.md`](../python/README.md). |
| `python/notebooks/` | An interactive marimo walkthrough of the method on simulated data. A demonstration, not a benchmark. |

## Question 1 — backward compatibility

| Script | What it establishes |
|---|---|
| `examples/cb2_generalization_proof.R` | The legacy representation identity, checked to machine precision, plus the local-equivalence illustration. |
| `examples/cb2_generalization_walkthrough.R` | The same argument in six worked examples, including hand-checkable numbers and 1,000 randomized identity checks. |
| `examples/barcs_input_output_examples.R` | Three designs — two-group, continuous dose, dose plus batch — printed as input table, call, and output table. |

These write no files. They print, and they fail loudly if an identity breaks.

## Question 2 — simulation

Two simulators, because they test different things.

**CRISPulator** produces a FACS screen: one phenotype per guide, cells sorted
into bins, generated by `julia/simulate_crispulator_facs.jl`.

How a script gets its screen varies, which is worth knowing before running a
long one unnecessarily. The baseline screen is **committed** under
`data/derived/crispulator_facs/`; the grid and genome-scale scripts call Julia
themselves and write per-run screens into the gitignored `results/` tree.

| Script | Question | Needs | Writes |
|---|---|---|---|
| `examples/simulation.R` | End-to-end demonstration on a continuous dose design. Generates its own data. | nothing | `results/simulation_summary.csv`, `figures/simulation_diagnostics.pdf` |
| `examples/crispulator_facs_benchmark.R` | Do the four guide-to-gene statistics differ on one screen? | the committed screen | `figures/crispulator_facs_benchmark.pdf` |
| `examples/crispulator_facs_repeated_benchmark.R` | Do those differences survive five seeds and a parameter grid? | Julia; simulates per cell | `data/derived/crispulator_facs_parameter_grid*.csv`, per-run screens under `results/` |
| `examples/crispulator_facs_moi_10k_benchmark.R` | **The headline result.** 10,000 genes, against MAGeCK-MLE and CRISPhieRmix, FDR scanned over thirteen cutoffs. | its own `--simulate` pass first | `data/derived/crispulator_facs_moi_10k_*.csv`, `figures/crispulator_facs_moi_10k_f1_by_fdr.pdf` |
| `examples/crispulator_facs_improved_barcs.R` | Does dispersion moderation help? Development split. | the committed screen | `data/derived/crispulator_facs_improved_barcs_*.csv` |
| `examples/crispulator_facs_improved_barcs_holdout.R` | Does it still help on fresh seeds? Held-out and confirmatory splits. | its own `--simulate` pass | (console, plus `results/`) |
| `examples/crispulator_facs_miss_cases.R` | Which genes do the comparators call that BARCS misses, and are they real? | committed inputs only | `data/derived/crispulator_facs_miss_*.csv` |
| `examples/crispulator_facs_mageck_permutation_resolution.R` | Is MAGeCK-MLE's flat strict-cutoff curve a real result or a resolution floor? | the genome-scale run | (console) |

**simCRISPR** produces a factorial screen: each guide carries a knockout
effect, a treatment effect, and an interaction. It simulates its own input, so
it needs no separate simulation step.

| Script | Question | Writes |
|---|---|---|
| `examples/simcrispr_interaction_benchmark.R` | Can BARCS recover an interaction *coefficient* — the estimand it exists for — and what does the choice of denominator cost? | `data/derived/simcrispr_interaction_*.csv`, `figures/simcrispr_interaction.pdf` |

### Why some of these come in pairs

`crispulator_facs_external_head_to_head.R` and
`crispulator_facs_f1_threshold_curves.R` each have an `_aggregate.R` partner.
The split is deliberate. The first stage fits every method on every screen and
writes per-run results; the second stage owns the *scope rule* — which runs
are in scope, and how they are pooled — and rebuilds the summaries from those
per-run files.

This exists because a scope rule was once wrong in a way that mattered. Pooling
across all parameter settings included the single-replicate runs, where the
design leaves one residual degree of freedom per guide and BARCS makes no calls
at all; that dragged the pooled F1 comparison into looking decisive when it was
not. With the stages separated, changing the scope rule is a cheap rerun of
stage two rather than a full refit.

## Question 3 — real screens

Each of these downloads its own input into the gitignored `data/raw/`.

| Script | Screen | What makes it worth running |
|---|---|---|
| `examples/sanson_benchmark.R` | Sanson A375 Brunello | Essential vs non-essential genes are a gold standard, and MAGeCK's official CNV correction can be switched on and off. |
| `examples/chronos_tzelepis_benchmark.R` | HT-29 time course | Genuinely longitudinal — pDNA plus seven timepoints — so the continuous design is not a re-labelled two-group comparison. |
| `examples/gse70038_comparison.R` | Glioblastoma, 64,747 guides | Published biology and an exact design-matched MAGeCK-MLE comparison. Binary, so it tests backward compatibility on real data. |
| `examples/waterbear_facs_benchmark.R` | GSE242880 IL2RA, four ordered bins | An ordered phenotype with a directionally validated gene panel to score against. |
| `examples/waterbear_facs_external_head_to_head.R` | the same screen | Adds rerun MAGeCK and the published Waterbear/MAUDE totals. |
| `examples/liang_cas13_benchmark.R` | Cas13 fitness, five cell lines | A different perturbation modality entirely, scored against deposited RobustRankAggreg results. |
| `examples/liang_hap1_specificity_volcano.R` | Liang HAP1 | Null-control specificity across p-value thresholds — a false-positive check, not a power check. |

The `scripts/` directory holds the fetch-and-count helpers these depend on
(`prepare_liang_cas13.R`, `count_liang_cas13_run.sh`,
`queue_liang_cas13_counts.sh`) and the two MAGeCK shims
(`mageck_compat.py` for runtime compatibility, `mageck_cnv_correct.py` for
direct access to its CNV normalizer).

## Where results live, and which are versioned

| Path | Versioned? | What it holds |
|---|---|---|
| `data/derived/` | yes | Compact summary tables. Every number in the manuscript traces to one of these. |
| `figures/` | yes | Built PDFs, one per benchmark. |
| `results/` | **no** | Bulky per-run intermediates and the per-run simulated screens. Regenerated by the benchmark scripts themselves. |
| `data/raw/` | **no** | Downloaded public datasets. Each real-data script fetches what it needs. |
| `output/pdf/` | yes | The built manuscript. |

The split is the reason a fresh clone looks half-empty and is not: everything
needed to *check* a claim is committed, and everything needed to *rebuild* it
is regenerable.

## Environment

Every toolchain is declared in [`pixi.toml`](../pixi.toml). Four are needed —
R for the method and benchmarks, Julia for CRISPulator, Python for MAGeCK, TeX
for the manuscript — and `pixi run doctor` reports which of them this machine
can currently run. See [`DEVELOPMENT.md`](../DEVELOPMENT.md) for the setup and
the two-repository submodule workflow.
